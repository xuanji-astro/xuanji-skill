# 一事一卜

问一件具体的事成不成、什么时候：六爻按他问的那一刻起卦，梅花按他报的数起卦，再加一节「玄玑怎么看」（从玄玑的服务器拿结论）。三家合起来答他嘴里那句问法，出一份手机上看的报告。

## 什么时候走一事一卜

只有两类：
1. **单独一件事的结果**：这个 offer 来不来、这笔钱要不要得回、这次合作成不成、这场纠纷怎么走。
2. **对方此刻的心思**：他现在怎么想、会不会联系、主不主动。

性格、人生阶段、一年怎么走，这些本命盘能答，不起卦；他拿这类问题来问卦，先引回本命或年度报告。一次塞进几件不相干的事，先拆开，一件一卦。

## 起卦前，先把问题问准

在心里定三件事：**他要什么结果、看到什么时候、对象是谁**。缺哪样，照「说话的样子」那样带出来，说成一个具体判断让他接，不用问卷式盘问。落卦前用一句陈述把问题钉死：「你问的是年底前能不能拿到这家公司的 offer」，他认了再起；他纠正的那句，才是真正的问题。

再不点破地问一句**这是谁的事**：他自己的（self）、别人托他来问的（proxy_asked）、他替别人操心主动问的（proxy_self）。

问的时限对应 `span`：七天之内的事写「七日内」，三个月之内写「一季内」，一年以上写「一年及以上」。

## 先收外应，再请他报数

**外应一定要问**，而且在起卦之前问，正面问、不给选项：

> 你决定问这件事的那一刻，正在做什么？当时有没有特别注意到什么画面、声音，或者旁边有人说了什么？

他说没有，就记成没有（`{"status":"none"}`），照常起卦，不硬凑；他说了什么就原样记下（`{"status":"given","text":"…"}`），不替他补画面。先看卦再问外应，容易倒着编，所以顺序不能反。

然后请他随口报三个数（一到四位都行，别想太久）。他不想报，就只用时间起梅花。

## 起卦

1. 把这次的问题写进 `yishi_request.json`，照 `SKILL.md` 第 2 步用 `create_private_json.mjs` 私有创建：

```json
{
  "question": "年底前能不能拿到这家公司的 offer",
  "question_type": "career",
  "asked_at": "2026-10-18T20:36+08:00",
  "numbers": [3, 8, 6],
  "waiying": { "status": "given", "text": "在地铁上，听见报站下一站人民广场，旁边有人打电话说已经定了" },
  "asker": "self",
  "span": "一季内"
}
```

   - `asked_at` 是**他问的那一刻、他当地的钟点**，带时区偏移，精确到分钟；不知道就问他在哪个城市、几点问的，不拿你这台机器的时间顶替。
   - `question_type` 九选一：career 工作求职升迁、relationship 感情、contact 联系音信、money 求财、litigation 纠纷官司、travel_near 近处出行、travel_far 远行、travel_abroad 出国、recovery 病愈。
   - `gender` 可选（male／female），问感情时用得上。

2. 起卦（本地算，不联网）：

```bash
node <skill目录>/scripts/yishi.mjs cast --input yishi_request.json --output yishi_cast.json
```

   打出 `CAST_SAVED` 就好了。卦面只认 `yishi_cast.json` 里的，不凭记忆补盘，不自己换算农历、干支、卦名、体用。

3. 「玄玑怎么看」：先跟他说一句，等他同意：

> 我再请玄玑那边看一眼：会把这件事属于哪一类、你问的时间和城市发给执天玄玑的服务器算一次，不发你问题的原话。可以的话回我一句「可以」。

   他同意了，写 `xuanji_request.json`（同样私有创建），只放这几样：

```json
{ "kind": "yishi", "question_type": "career", "asked_at": "2026-10-18T20:36+08:00", "city": "上海" }
```

   在中国以外的城市，不写 `city`，写 `lat`、`lon`（保留两位小数）。然后：

```bash
node <skill目录>/scripts/client.mjs xuanji --input xuanji_request.json --output xuanji_view.json
```

   回来的是结论：`verdict`（成／悬／不成）、`effort`（要费点力／会慢一点／没有）、`reason`（一句白话）、`window`（最可能的那段）、`next_window`（下一段）。**玄玑怎么算的，不问、不猜、不解释**；对用户就说「玄玑看」，把结论和那句理由翻成他听得懂的话。他不同意发，这一节就不写，报告里玄玑那一家写成「这次没看」。

## 六爻怎么断

用神按问的事取，`yishi_cast.json` 里 `liuyao.yongshen` 是程序的粗选，你复核：

- **先定谁的事**：本人的事、别人托来问的，世爻都当他本人；他替别人操心主动问的，先取那个人对应的六亲当「人位」（朋友＝兄弟、父母＝父母、子女＝子孙、伴侣＝女问官鬼男问妻财，没给性别取应爻），再看事的用神跟人位的关系。
- **再按事取用神**：工作求职＝官鬼（父母＝单位文书作辅）；感情＝女问官鬼、男问妻财，没给性别或同性看应爻；联系音信＝父母（应爻＝对方作辅）；求财＝妻财（子孙是钱从哪来，兄弟是谁来分钱，两样必看）；纠纷＝官鬼加世应（父母＝文书）；出行＝世爻加应爻（子孙看平安、官鬼看阻碍）；出国＝父母（证件）加世应；病愈＝官鬼是病、子孙是医药、世爻是本人，三样一起看。

断的顺序：
1. 定人位和用神；用神出现几次，按明伏、动静、旺衰、空破、跟世应的远近挑主次。
2. 看世爻、应爻的状态。
3. 顺着每一个动爻追到变爻：化进化退、回头生克、化空化墓；只讲动爻的变化，不把静爻编成变化。
4. 月建、日辰定旺衰和时机：临、生、合、冲、破、入墓。
5. 伏神看飞伏关系，什么时候透得出来。
6. 六合六冲、卦变定大方向：六合变六冲是先聚后散，六冲变六合是先难后易。
7. **取象翻成今天的样子**：卦里的六亲、六神、卦象，古书写的是古时候的样子，你要自己翻成它在今天的样子，再按这个人的现实判断是哪一种。父母爻从前是纸契书信，今天也可能是电子合同、聊天记录、线上流程；兄弟从前是同辈朋友，今天也可能是同行、合伙人、群里的人。说最可能的那一种，不并列一串。

证据分轻重：月建、日辰、动爻、六神不机械计票；先确认某条生克冲合真的作用到世、应、用神上，才当主证据给结论；作用不到的只当辅助，给质地（什么人、什么形式、什么氛围）。

日子：`liuyao.timing` 里程序算好的日子直接用，不自己心算干支。报法是一个窗口加最可能的一天，最多再给一个「这波没动静，下一波看哪」；用神不空不破、没有要等的结，就说「六爻没给死日子」，不硬凑。

## 梅花怎么断

1. **外应先读**：只用他自己说过的话取象，跟所问的事连起来讲（人在车里往前走＝事情已经上路；报的是「下一站」＝还没到）。他说没有，这一段就不写。
2. **体用**：动的那一卦是用，静的是体；用生体、体用比和、体克用、体生用、用克体，要结合问的事解释，不直接换成吉凶。体卦在这个月是旺是衰（`tiYong.ti.seasonState`），说明底气足不足，不单凭它说必成必败。
3. **本卦、互卦、变卦**：本卦看现在，互卦看过程，变卦看往哪变。卦辞、动爻的爻辞照 `meihua.texts` 逐字引用，再翻成今天的样子。
4. **日子**：`meihua_timing` 里算好了：本卦上卦数加下卦数加动爻数是基数，体卦旺就取近、衰就加倍，单位跟他问的时限走。报法是一个日子或一旬，加一句迟速（「你这边当令，按快的算」），不并列几个候选。

## 三家合起来

- **答的是他嘴里那句问法**：问「能不能成」，能成但要等就是「成」，把等什么、等到什么时候讲清楚；问「快不快」，快不起来就是「悬」，悬不是不成，要说清等什么条件。
- **三家同向就说满**；不同向就说「悬」，讲清两边各卡在哪，不拿一家压另一家。
- **日子听谁的**：六爻给了日子用六爻；六爻没给，用玄玑的窗口当主；梅花的日子当第二个点。日子一律抄程序给的，标清是哪一家给的。
- 每家的依据只用那一家盘上有的，别家的证据不安到它头上。

## 安全边界

问到自伤伤人、怀孕母婴、医疗生死、失踪犯罪、倾家荡产这一类，不起卦、不断吉凶：先接住他的担心，说清卦不判这个，给现实的去处（就医、报警、找律师），能帮的话帮他把时间线、要问医生的问题理一理。纠纷官司只判倾向（成／悬／不成、卡在哪），不给法律做法。

## 报告

问完、起完、断完，用户要报告就出一份一事一卜报告：写 `yishi_report.json`（私有创建），再执行：

```bash
node <skill目录>/scripts/build_doc.mjs --kind yishi --cast yishi_cast.json --view xuanji_view.json --report yishi_report.json --out yishi.html --pdf yishi.pdf
```

（玄玑这次没看就不带 `--view`。）脚本查字段、字数、禁用词，画好整页，逐项核对完整才出文件；出不了完整的就照 `SKILL.md` 第 6 步，什么都不给、请他加创始人微信。

### 报告分四卷

封面：一枚印章（成／悬／不成）、三行判词（第一行是这一卦卦辞或爻辞里最贴的几个字，后面两行把它翻成今天的话）、他问的那句原话和时间地点、三家同看三行、四卷目录。

1. **一眼看懂**：答案加最要紧的日子（标是哪家给的），下一个点；三个要点；「接下来的几步」时间轴。
2. **三家交叉**：三圈交叠图（每家自己看到的、两家都这么说的、正中间三家都说的）；结论、日子、重点三行对照；一段话讲答案为什么是它、日子听谁的。
3. **路怎么走**：局势图（对方缺什么、你握着什么、中间要防什么）；路线图（主路和一两条岔路，顺着箭头走到落定的那一天）；军师谏言。
4. **分开细看**：六爻、梅花、玄玑各一张卡，每张先一句结论，再一步一步看，每一步标作用（帮你／要防／时间／定位／方向），决定结论的那一两步标「关键一步」。六爻卡带爻图，梅花卡先写外应、再写起卦算式和本互变三卦，玄玑卡只写结论、要费力在哪、接上的日子。

收尾：「回到你的问题」三级台阶（现在先做什么、最关键的那一步、到那天看什么），「一句话记住」，一张「到时候回来发这一句」的对话卡；再是「接下来可以问我」、创始人那张卡。

### 写法

- 第一句就是答案，用「你」直接说；正文不用问句。好话多说，难处翻过来说成怎么做。
- 古书原文配今天的样子：引一句，紧跟着说它放在他这件事上是什么。
- 局势图照这个顺序想：他的处境 → 对方缺什么 → 他握着什么 → 怎么谈、怎么走 → 风险只说一两句。
- **军师谏言**：按这件事的行当，请一位这一行公认最懂的真人（只用他公开的身份和公开讲过的办法），落到他身上给一条能照着做的建议。不写死固定的几个名字，每份按事挑。
- 盘上一条线管两种可能时，不硬猜是哪种，建议两种各给一条。
- 不写「那股劲」「这股劲」「带劲」，不连着用「亮」做比喻；收尾不用「X 不轻，但……」这种拧着的转折。
- 「一句话记住」和「关键一步」用醒目的标，夸人的块用醒目的颜色，不用灰。
- 报告是静态页，不放读者点了没反应的勾选框；要他做的事写成「回到对话里发这一句」。

### 机关：把他带回对话

玄玑那张卡后面接一张对话卡，二选一：

> 「这件事放在我今年的运里是什么位置」 → 接到年度报告
> 「三套盘各自怎么看我的××」 → 接到分术报告（××换成这件事所在的那一块，比如事业、钱、感情）

收尾那张写「到时候回来发这一句」：「玄玑，××那件事有结果了」 → 回来对一对。他回来说了结果，照 `SKILL.md`「对过的事」记下来，下一份报告里那一条打上勾。

## 追问

同一件事的追问，沿用原来那一卦，不重新起，不拿今天的日子重算；事情起了实质变化、或者他坚持要问新的一件，说清这是新的一件，再起一卦。
