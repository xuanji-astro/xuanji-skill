# 合盘：两个人怎么看

用户问自己和另一个人的关系时用：合不合、这段关系怎么样、TA 是什么样的人、我们会怎么走。主语永远是用户（「你」），对方（「TA」）是坐标：讲的是你在这段关系里是什么位置、拿到什么、怎么用自己。

合盘只在对话里做：不写报告文件，不出 HTML，也不把对话整理成文档。用户要合盘报告、完整版、「整理一份」时，直接说这一版合盘只在对话里讲，不手写文件绕过。

## 1. 收 TA 的信息（一次问完）

- TA 的出生日期、时间、城市、性别，以及这个时间是从哪来的。
- 你们现在是什么关系：恋人、暧昧、前任、家人、朋友、同事、合伙、客户、其他。顺带问一句哪年认识的，不记得就算了。**关系只听用户说，不从盘里猜，也不默认是恋爱。** 用户没说就不追问，传「其他」，按通用来读。
- 用户自己的出生信息：这次对话里已经给过就直接复用，不要在对话里复述。
- TA 的时间不知道也照样做，直接告诉用户少了哪些：西盘和底色配对整块出不了，只看宿缘和八字。
- 调接口前照 `SKILL.md`「数据与范围」说明两个人的信息发到哪、本地会留什么，取得用户同意，并确认用户有权提供 TA 的信息。不复述 TA 的完整生辰。

## 2. 调接口

用 `node <skill目录>/scripts/client.mjs pair --input request.json --output pair.json`（请求为 `{a,b,relation,met_year?}`），请求按SKILL第2步经标准输入私有创建；请求和结果文件只放本次授权目录，macOS权限已经验证，其他环境未验。字段见 `docs/api.md`。不要自己算两张盘之间的任何东西。

宿主没有独立标准输入通道时，使用 `node <skill目录>/scripts/create_private_json.mjs --empty request.json`（报告稿用 `report.json`）先独占创建空的600文件，再用宿主正常允许的写文件工具原地写入JSON。禁止用printf、heredoc、重定向或命令参数承载JSON，不关闭安全检查。写后用 `stat -f '%Lp' request.json` 核对600；客户端/构建脚本再检查本人所有权、常规文件和权限。工具若替换文件导致权限改变，应停止，不发送、不构建，不用chmod补救，只重新创建本次生成的文件。宿主对话和写文件工具记录仍可能保留内容。

## 3. 第一屏（不超过 300 字）

1. **这是一段什么缘。** 宿缘本命（`xingxiu.benming`：关系名、远近、你演哪一方），再配西盘最响的一条和八字一条。三套指向一致的才说。
2. **TA 在你这里落在哪、给了你什么。** 看 `west.overlay` 和 `west.engage`。
3. **现在的时机。** 两个人各自的大运顺逆和今年感情亮不亮（`timing.now`），一句话。

不报分数，不用「合」「不合」两个字下结论。

## 4. 两人验前事（有才做）

- 用户说了哪年认识，调接口时传 `met_year`，接口只留认识以后的年份。
- 只从 `timing.both_lit_past` 里挑：两个人同一年、同一块（感情或家庭）都亮的年份。按 `strength` 从高往低，最多 2 条。没有就跳过，不拿一个人亮的年份凑。`love_base_rate` 大于 0.2 的也跳过，那说明两人同亮太常见，没有区分力。
- 说到「那一年你们之间有一次大变化」为止，可以给几个同类选项（走近、定下来、分开），不硬说是哪一种。没传 `met_year` 时，那一年两人可能还不认识，说的时候要留这个口子。
- `timing.half_lit_internal` 是内部记账，不对用户说。
- 说成一件两个人之间的事，用户回一次准、部分准、不准就行，不要拆成你那份、TA 那份。答「准」的，后面引用时说「你确认过」；答「不准」的，不再当事实用，也不换个说法再提。

## 5. 往下展开

用户问具体问题时，一个问题只做一次综合，格式和颗粒度同 `SKILL.md`「按用户的问题展开」。用户要「完整看看」时，按下面的顺序讲，每块两三句：

| 讲什么 | 用哪些字段 |
|---|---|
| 缘：什么缘、来路还是去路 | `xingxiu`（本命为主，值日是表层）、`west.nodes`（TA 的星合你的南交或北交，8° 以内才算） |
| 吸引从哪来、谁更着迷 | `west.eros`（只有恋人和通用口径才有）、`bazi.hits` 里的日干五合、桃花红鸾 |
| TA 落在你哪、你们互相给了什么 | `west.overlay`、`west.engage`（你缺的星、TA 递来的星、对称度、谁在被供） |
| 反复上演的那一幕 | `west.anchors.四`、`matrix.dims` 里的制约信号 |
| 谁在主导、你的杠杆 | `west.anchors.五`、`west.persona`（两人的出厂底色和配对） |
| 会在哪里疼 | `west.anchors.六`、`matrix.dims` 的制约 |
| 时机 | `timing.now`、`timing.both_lit_future`；两个人各自的依据分开说 |
| TA 在你命里是来做什么的 | `west.anchors.七`；留余地，不判死 |
| 六项一览 | `matrix.dims` 每项的档位、`matrix.type` 关系类型 |

- **各自的承载力**（`capacity.you`、`capacity.ta`）：每个人在关系里能给什么、需要什么、压力下会怎么失衡。吸引再强也盖不住承载不足，长期承载是「条件式」或「承载不足」时要说清楚条件是什么。
- **八字合婚**（`bazi.hits`，每条带分量 `w`，正为支持、负为制约）：分量最重的是夫妻宫（日支）、喜用互补、夫妻星三条。**天合地合**是八字里最强的一条，可以单独说；其余当佐证，跟西盘指向一致才单独说。
  - 生肖（`bazi.shengxiao_note`）只当一句「家里人眼中的合不合」，不进结论。
  - `bazi.score_internal` 不对用户报，也不换算成分数说。
  - 日主相生要说清方向：谁付出多、谁受滋养。

## 铁律

1. **主语是你。** 「你们」只在讲结构时用。讲处境、感受、怎么办，主语都是「你」。
2. **不评判 TA。** 只说结构，不说人品。不说 TA 不爱你、在利用你、是哪种人。
3. **不替 TA 表态。** 盘看得出 TA 的哪些点被你触动，看不出 TA 心里怎么想。暗恋、单向的关系只说你这边的投射有多强、TA 的哪里被碰到。
4. **程度听接口的。** 杀伤力档（`west.eros.杀伤力档` 和 `档位边界`）、六项档位、关系类型都由接口算好，说轻说重都不行。家人、朋友、同事口径不写性张力。
5. **换位要对得上。** 同一对人从 TA 的视角看，事实相同、方向相反。方向（谁在被供、谁更着迷、谁更费劲）照接口原样说，不自己调。
6. **主体性两头都不偏。** 不劝用户改掉自己去迁就 TA，也不劝用户离开这段关系。杠杆是用你本来的优势。
7. **夸要有证据。** 每句夸都挂在一件具体的东西上：哪颗星、落在哪宫、TA 补了你哪一行。这句放进别人的合盘里也成立，就删掉重写。
8. **关键判断点名星和宫**，接一句这颗星或这一宫管什么，再翻成日子里的一个画面。只报星名宫位不算说完。
9. **每个风险配修复资源**：吉星的相位、承载项里的支持信号、时机。只吓人不给出路就是没写完。
10. **用户讲的经历只用来对照**，不拿来反推结论。
11. **现实安全不交给盘。** 用户提到暴力、控制、骗钱、权力严重不对等时，直接说这是现实里的安全问题，建议找身边可信的人或专业帮助，不用星盘去解释或淡化。
12. **时间不准就收窄。** `scope.confidence` 是「中」时，宫位相关的话留余地；是「低」时，西盘整块不出，只讲宿缘和八字。
13. 牵星印（`west.seal`）可以在结尾提一句档位名，不报数字，不当分数用。

## 接下来可以问我（合盘版）

同 `SKILL.md`「接下来可以问我」的挑法。人在合盘里最想问的是：TA 心里我是什么位置、TA 会不会主动、我们什么时候能定下来、吵架了怎么和好、能不能一起做事、家里人那关。问题往这对盘有把握的地方引：两人同亮的年份、六项里信号最多的那几项、用户确认过的验前事。
