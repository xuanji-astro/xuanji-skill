# 定时辰：出生时间卡在时辰交界时

0.1.1 起，定时辰交给执天玄玑网站的「时辰校准」（分界辨识校准法，免费）。Skill 这边只做两件事：看出生时间卡不卡在时辰交界，卡的话带用户去网站校准；用户挑好时间回来，按新时间重排。

本地不再拿经历给两张盘打分（`rectify.mjs ask`、`rectify.mjs score` 不再用）：拿经历倒推出生时间，我们用 206 位有出生记录的名人测过，跟随手猜差不多。

## 什么时候提

拿到 `profile.json` 后先跑：

```bash
node <skill目录>/scripts/rectify.mjs check --profile profile.json --request request.json --output request_alt.json
```

- 打出 `RECTIFY_NOT_NEEDED`：不提这件事，照常往下讲。时间来源是出生证的，脚本也不会提。
- 打出 `RECTIFY_CANDIDATE_SAVED`：第一屏说完「出生时间可信度」以后、验前事之前，说一次下面这段。交界是哪两个时辰，看 `method.boundary.hour`：`branch` 是现在这个；`minutes_to_next` 比 `minutes_from_prev` 小，另一个就是 `next_branch`，反过来就是 `prev_branch`。脚本顺手存的 `request_alt.json` 这一版用不上，不用管它。

> 你的出生时间卡在巳时和午时交界，八字最后一柱、上升和宫位都可能跟着变。想定下来，可以去执天玄玑网站用「时辰校准」，免费：
> 1. 打开 xuanji-astro.com，登录；
> 2. 进「宝殿」里的「我的档案」，新建或打开你这份档案，填好出生日期和城市；
> 3. 点出生时间旁边的「时辰校准」，一层一层挑出最像你的那一段；
> 4. 挑好的时间回来告诉我，我按新时间重排。

用户不想去，就照「这里还没定下来」往下讲，同一次对话里不再提。

## 用户带着挑好的时间回来

1. 照 SKILL 第 2 步私有创建 `request_cal.json`：内容跟 `request.json` 一样，只把 `time` 换成他挑的时间（`HH:mm`；他说的是一段，比如 17:30–17:32，取中间那一分钟），`time_source` 写 `family_clear`，`time_precision` 写 `minute`。不覆盖原来的 `request.json`。
2. `node <skill目录>/scripts/client.mjs profile --input request_cal.json --output profile_cal.json`。
3. 说一句「按你在网站时辰校准里挑的时间排」。之后的解读、验前事、报告一律用 `profile_cal.json`（出报告 `--profile profile_cal.json`，自查 `--request request_cal.json`）；再排印占、紫微也用 `request_cal.json` 里的时间。
4. 这个时间就当定了：`rectify.mjs check` 不用再跑，同一次对话里不再建议校准，也不再建议找出生证。

他回来说的时间跟原来的一样，也照上面做（来源换成网站挑的）。

## 报告里怎么写

- 校准过的：`progress` 写一条 `{"state":"已确认","item":"出生时间按网站「时辰校准」里挑的时间排"}`。
- 没去校准的：`progress` 写 `{"state":"待确认","item":"出生时辰在巳时和午时之间，还没定下来"}`，再按 `open_question` 的写法讲清楚会影响哪几块（时柱、上升、宫位），最后带一句可以去网站「时辰校准」定下来。跟时柱、上升、宫位有关的结论两种都说，说成区间，不说成定论。
- 0.1.0 以前用旧办法定过时辰、手上有 `rectify.json` 的，`build_report.mjs` 还收 `--rectify rectify.json`；新的对话不用它。

## 隐私

时辰校准在网站上做，按网站的用户协议和隐私政策。Skill 这边只多两份文件 `request_cal.json`、`profile_cal.json`，跟 `request.json` 一样只建在本次工作目录，不会自动删除。
