# 定时辰：出生时间卡在时辰交界时

出生时间离时辰交界很近、来源又不是出生证时，八字最后一柱（时柱）可能是两个里的一个。这里用两张盘对用户自己的经历，看哪张更贴。（10-10 改过问法：大事要说具体的事和好坏，补问问具体的事，不再问「有没有明显的变动」「整体往上还是往下」。）**分数只由 `scripts/rectify.mjs` 算，你不要自己判、不要自己挑年份、不要改阈值。**所有文件（`request_alt.json`、`profile_alt.json`、`events.json`、`ask.json`、`answers.json`、`rectify.json`）都建在用户的当前工作目录，不进 Skill 目录（见 SKILL「文件放在哪」）。

## 什么时候提

拿到 `profile.json` 后先跑：

```bash
node <skill目录>/scripts/rectify.mjs check --profile profile.json --request request.json --output request_alt.json
```

- 打出 `RECTIFY_NOT_NEEDED`：不提这件事，照常往下讲。时间来源是出生证的，脚本也不会提。
- 打出 `RECTIFY_CANDIDATE_SAVED`：第一屏说完「出生时间可信度」以后，问一句要不要定下来。交界是哪两个时辰，看 `method.boundary.hour`：`branch` 是现在这个；`minutes_to_next` 比 `minutes_from_prev` 小，另一个就是 `next_branch`，反过来就是 `prev_branch`。

> 你的出生时间卡在巳时和午时交界，八字最后一柱会因此不同。想定下来的话，我会用交界另一侧的时间再算一次，再问你几个过去的事，大概两分钟。

用户不想定，就跳过，照「这里还没定下来」往下讲，不再追问。

## 流程

1. **再算一次**（用户同意了才做）：`node <skill目录>/scripts/client.mjs profile --input request_alt.json --output profile_alt.json`。这次发的还是同一份出生信息，只是时间挪到交界另一侧。
2. **请用户说大事**：
   > 说几件你记得清的大事：哪一年、什么事，对你来说是好事还是坏事。比如「2018 年结婚，好事」。
   > 可以从这几方面想：感情、事业、钱财、学业、健康、家庭。有孩子的话，也说一下每个孩子是哪年出生的（1 月、2 月出生的，说一下几月几号）。
   - 身强身弱校正时用户已经说过大事的，直接用上，说一句「前面说过的我直接用上」，只请他补。
   - 每件事归到一个方面和这个方面里最像的那件事（下表），再记好事还是坏事。用户没说好坏的，问一句「对你来说是好事还是坏事？」；说不上来的，`good` 不写。哪件都不像的，只写方面、不写 `event`。
     | 方面 | 可选的事 |
     |---|---|
     | 感情 | 初恋、遇到正缘、订婚、结婚、冷战、分手、离婚、复合、被骗 |
     | 事业 | 找到工作、升职、降职、跳槽、创业、公司倒闭、失业、转行 |
     | 钱财 | 第一桶金、投资赚钱、意外之财、买房、买车、投资亏损、负债、破产 |
     | 学业 | 高考、考研、留学、休学、考试受阻、考证、获奖 |
     | 健康 | 大病、意外受伤、心理困扰、减肥成功 |
     | 家庭 | 孩子出生、亲人离世、安家置业、搬家移民、家道中落、家庭变故 |
   - 用户说了「孩子出生」的，那一年也写进 `children`（1 月、2 月出生的再问几号）。
   - 只写方面、那件事、年份、好坏，**不写用户讲的细节**。按 SKILL 第 2 步私有创建 `events.json`：
     ```json
     {"events":[{"year":2016,"domain":"事业","event":"跳槽","good":true},{"year":2022,"domain":"钱财","event":"投资亏损","good":false}],"children":[{"year":2019,"month":6}]}
     ```
     没孩子写 `"children":[]`。最多 12 件大事、6 个孩子。**这个文件不发给接口**，只给本地脚本打分。（身强身弱校正交给接口的 `calib.events` 就是这同一份 `events`，那一份要发给接口，见 SKILL.md。）
   - **这些细节也不进后面的解读和报告。** 你对用户说过「只记哪年、什么事、好坏」，后面就要做到：讲到这几年，只按「年份＋那件事」提，比如「你提到 2019 年跳槽」；不复述学校、公司、职位、对象、投资方式这类细节，也不拿它们出「接下来可以问我」的题。
3. **出要问的题**：`node <skill目录>/scripts/rectify.mjs ask --a profile.json --b profile_alt.json --events events.json --output ask.json`
4. **照 `ask.json` 问**：
   - `targeted`：专挑两张盘说法相反的年份。`question` **一字不改**地问，几题一起问就行。用户回「有／没有／记不清」，别的说法照意思归到这三个里。
   - 答「有」的，接着问 `follow_up`（「对你来说是好事还是坏事？」），记「好事／坏事」；说不上来就不记。
   - **零暗示**：不说「按某张盘你那年该有」，不说哪一年是为哪个时辰问的，不提示可能是什么事（`question` 里的「比如」是固定的，不另加）。允许「记不清」，不引导回忆。
   - 不再单独问「那一年整体往上还是往下」：好坏只从大事和追问里来。
5. **打分**：回答按第 2 步私有创建 `answers.json`，没问的题不写；`good` 只写答了「有」的：
   ```json
   {"targeted":{"t1":"有","t2":"没有","t3":"记不清"},"good":{"t1":"好事"}}
   ```
   `node <skill目录>/scripts/rectify.mjs score --a profile.json --b profile_alt.json --events events.json --ask ask.json --answers answers.json --output rectify.json`

## 怎么判（脚本已经算好，你只读结果）

- **第一票**：用户说的大事（按那件事归到工作、事业认可、感情、家庭、钱、迁移远方；健康不算）和专门问的年份，两本账分开记、合在一起判。一边的权重和要高出另一边 25% 以上，并且至少 2 件站在这一边，才记这一票。不到就不记，宁可存疑。
- **第二票**：体感。用大事和追问里的好事坏事：只看两张盘对那一年说法相反的（一张说顺、一张说闷），好事记给说顺的那张，坏事记给说闷的那张；同一年好坏都有的那年不记；至少 2 件指向同一张，且多过另一张。两张盘喜忌一样，或者说的事都不在这些年份上，这一票就空着。
- **子女**：不单独成票。两票一比一时用来打破平局；一票都没有时，只给一个倾向，不拿它定。
- 结果 `result`：`a`＝原来的时间，`b`＝交界另一侧，`uncertain`＝时辰存疑。`hours` 给出两边各是什么时辰。

## 判完怎么说、怎么用

- **`a`**：「按你说的这些，你更像是生在巳时，就按原来的盘往下讲。」后面照常用 `profile.json`。
- **`b`**：「按你说的这些，你更像是生在午时。」之后的解读、验前事、报告**一律改用 `profile_alt.json`**，出报告时 `--profile profile_alt.json`。不要报具体到分钟的时间：那只是交界另一侧的一个代表时间。
- **`uncertain`**：「两边还分不出来，时辰先存疑。」跟时柱、上升、宫位有关的结论两种都说，说成区间，不说成定论。其他照常讲。
- 用户问「为什么」时，才讲依据：说了几件大事、各站在哪边，专门问的几年怎么答的，好事坏事落在哪边。不报权重、分数、百分比。
- 出报告：
  - 定了的（`a` 或 `b`），在 `progress` 里写一条，例如 `{"state":"已确认","item":"出生时辰定在午时：大事和体感都更贴这边"}`；
  - 存疑的，写 `{"state":"待确认","item":"出生时辰在巳时和午时之间，还没定下来"}`，再按 `open_question` 的写法讲清楚会影响哪几块；
  - 怎么定的写进 `basis.notes`，只写年份和方面，不写用户讲的细节。
  - 出报告时加 `--rectify rectify.json`：`node <skill目录>/scripts/build_report.mjs --profile profile.json --report report.json --rectify rectify.json --out report.html`（结果是 `b` 时 `--profile profile_alt.json`）。定了的，报告表头写「出生时辰经定时辰定在某时」，不再报离交界几分钟、两种口径的时柱、压宫头的星；存疑的照原样。脚本打出 `RECTIFY_PROFILE_MISMATCH`，说明 `--profile` 用错了那张盘。
- 定下来以后，就当定了，不再反复建议复核（铁律 9）：`progress` 里不再加「具体几分」之类的待确认，也不再建议找出生证。上升、宫头、星压宫头这些要精确到分钟的说法，定时辰管不到（`b` 那张盘用的又只是代表时间），解读和报告里都不报；用户问到上升或宫位，就说这要精确到分钟，定时辰只定到时辰。

## 这一版不做的（后续版本）

- 晚年佐证：时柱主 48 岁以后，问法要另写。
- 时辰完全不知道的（12 个候选）：照旧按三柱排，缺时柱的结论不说。
- 上升、天顶卡在换星座边界的：只照 `method.boundary` 如实说，不做打分。

## 隐私

定时辰用的大事、孩子的出生年份、回答，都只存在本次工作目录里的私有文件（`events.json`、`answers.json`、`ask.json`、`rectify.json`）里，由本地脚本打分，**不发给执天玄玑接口**。接口只收到两次同一份出生信息（第二次时间不同）。这些文件不会自动删除，告诉用户它们在哪，不需要了可以自己删；宿主的对话记录里仍可能留着用户说过的话。
